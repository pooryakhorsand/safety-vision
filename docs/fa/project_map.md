# نقشه‌ی پروژه (راهنمای فارسی)

این فایل توضیح می‌دهد هر پوشه و فایل برای چه بخشی است، تا هنگام توسعه بدانید کجا را تغییر دهید.

## اصل کلی

- **کد ثابت، پروفایل متغیر:** هر چیزی که از یک مشتری به مشتری دیگر فرق می‌کند (اسم، لوگو، رنگ، زبان، ماژول‌های فعال، مدت نگهداری داده) فقط در `profiles/` است.
- **هر بخش یک app جدا:** هر app جنگو یک مسئولیت دارد و فایل‌هایش همیشه همین اسم‌ها را دارند:
  `models.py` (جدول‌ها)، `views.py` (منطق صفحه‌ها)، `urls.py` (آدرس‌ها)، `forms.py` (فرم‌ها)، `admin.py` (پنل ادمین جنگو)، `tests.py` (تست‌ها).
- **جنگو فقط نمایش می‌دهد:** هیچ پردازش تصویری در جنگو نیست. Engine با محیط مجازی خودش در `engine/` اجرا می‌شود.
- **فقط جنگو صاحب دیتابیس است:** Engine رویدادها را با API توکن‌دار به جنگو می‌فرستد و هیچ‌وقت مستقیم به دیتابیس وصل نمی‌شود. قرارداد کامل در `docs/engine_api.md` است.

## ریشه‌ی پروژه

| مسیر | کاربرد |
|---|---|
| `VERSION` | **تنها جای شماره‌ی نسخه**؛ وب، Engine، heartbeat و نوار پایین از همین می‌خوانند |
| `.env.example` | نمونه‌ی تنظیمات این سیستم: کلید امنیتی، دیتابیس، مسیر داده و پشتیبان، توکن Engine. یک کپی با نام `.env` بسازید. |
| `requirements.txt` | کتابخانه‌های لازم برای اجرا |
| `requirements-dev.txt` | ابزارهای توسعه (کامپایل ترجمه) |
| `profiles/default/profile.yaml` | **برندینگ و تنظیمات مشتری**: اسم محصول، اسم کوتاه (`short_name`، برای پوشه‌ها و نام نصب‌کننده)، اسم سایت، لوگو، رنگ، زبان، منطقه‌ی زمانی، مدت نگهداری رویدادها (`retention_days`)، ماژول‌های فعال |
| `profiles/default/assets/logo.svg` | لوگوی مشتری |
| `data/` | **داده‌ی تولیدشده‌ی سیستم** (در گیت نیست): `media/` تصاویر و کلیپ رویدادها، `backups/` پشتیبان‌های دیتابیس |
| `deploy/docker-compose.yml` | PostgreSQL اختیاری برای نصب سرور چندکاربره (نسخه‌ی دسکتاپ از SQLite استفاده می‌کند) |
| `engine/` | موتور پردازش GPU با محیط پایتون جدا؛ همه‌ی پردازش تصویر اینجاست |
| `desktop/` | launcher، اسکریپت ساخت و نصب‌کننده‌ی ویندوز |
| `scripts/compile_translations.py` | تبدیل فایل ترجمه‌ی `.po` به `.mo` بدون نیاز به gettext |
| `docs/engine_api.md` | قرارداد ارتباط Engine و جنگو |
| `docs/architecture.md` | معماری، چرخه‌ی عمر رویداد و راه افزودن ماژول (انگلیسی) |

## پوشه‌ی `web/` (جنگو)

### `web_config/`: تنظیمات کل پروژه

| فایل | کاربرد |
|---|---|
| `settings.py` | تنظیمات جنگو: زبان‌ها، دیتابیس، `APP_DATA_DIR` (پوشه‌ی داده‌ی برنامه‌ی نصب‌شده)، لاگ چرخشی، بررسی کلیدهای امنیتی (حداقل ۳۲ کاراکتر) |
| `urls.py` | نقشه‌ی اصلی آدرس‌ها؛ هر app آدرس‌های خودش را دارد |
| `wsgi.py` / `asgi.py` | نقطه‌ی ورود سرور (در نسخه‌ی دسکتاپ با waitress) |

### `apps/core/`: ابزارهای مشترک

| فایل | کاربرد |
|---|---|
| `profile_loader.py` | خواندن و بررسی `profile.yaml` |
| `context_processors.py` | متغیرهایی که در همه‌ی قالب‌ها هست: `brand`، `app_version`، `vision_modules` |
| `permissions.py` | دکوریتورهای `@login_required`، `@admin_required` و `@engine_token_required` (برای API Engine) |
| `templatetags/ui_tags.py` | تگ `{% icon "نام" %}`، `{% nav_active %}` و فیلتر `hms` (نمایش مدت زمان) |
| `views.py` | API وضعیت سیستم (`/api/system/status/`) و دریافت heartbeat از Engine (`POST /api/engine/heartbeat/`) |
| `engine_status.py` | آخرین heartbeat را در cache نگه می‌دارد؛ بدون heartbeat بیش از ۲۰ ثانیه یعنی Engine آفلاین است |

### `apps/accounts/`: کاربران و نقش‌ها

| فایل | کاربرد |
|---|---|
| `models.py` | مدل `User` با فیلد `role` (ادمین / اپراتور) |
| `forms.py` | فرم ورود و فرم ساخت کاربر |
| `views.py` | ورود، خروج، لیست کاربران، ساخت کاربر، فعال/غیرفعال کردن |
| `tests.py` | تست دسترسی‌ها (اپراتور نباید به صفحات ادمین برسد) |

### `apps/cameras/`: دوربین‌ها

| فایل | کاربرد |
|---|---|
| `models.py` | جدول `Camera`: نام، آدرس منبع، **ماژول‌های این دوربین** (`modules`)، فعال بودن، ترتیب. لیست `modules` خالی یعنی همه‌ی ماژول‌های فعال. |
| `api.py` / `urls.py` | `GET /api/engine/cameras/`: Engine لیست دوربین‌ها را از اینجا می‌خواند |
| `views.py` / `forms.py` / `page_urls.py` | **صفحه‌ی مدیریت دوربین** (فقط مدیر): افزودن، ویرایش، فعال/غیرفعال، حذف، و وضعیت زنده از heartbeat Engine |
| `sources.py` | قانون‌های آدرس منبع (rtsp، http، مسیر فایل، شماره‌ی وب‌کم) و پنهان کردن رمز در نمایش |

### `apps/vision_modules/`: ماژول‌ها

| فایل | کاربرد |
|---|---|
| `registry.py` | **لیست همه‌ی ماژول‌ها و نوع رویدادهای هر ماژول** (فعلاً ماژول `ppe`: `no_helmet`، `no_vest`، `no_safety_shoes`). ماژول جدید فقط اینجا اضافه می‌شود. |

### `apps/people/`: افراد (کارکنان)

| فایل | کاربرد |
|---|---|
| `models.py` | جدول `Person`: کد پرسنلی، نام، واحد، فعال بودن. بدون عکس و بدون داده‌ی بیومتریک. |
| `views.py` / `urls.py` | لیست و جستجو، پروفایل (۳۰ روز اخیر)، افزودن/ویرایش/غیرفعال‌سازی (فقط مدیر) |

### `apps/events/`: رویدادها و کانال مدیریتی

| فایل | کاربرد |
|---|---|
| `models.py` | جدول `Event`: یک تخلف با زمان شروع و پایان، دوربین، ماژول، نوع، شناسه‌ی فرد، تصویر، وضعیت (باز/تأیید شده)، چه کسی و کِی تأیید کرد |
| `ingest.py` | **دریافت رویداد از Engine**: بررسی داده و ساخت/به‌روزرسانی رویداد با `uid`؛ `ended_at` خالی = بازگشایی مجدد (تکرار تخلف همان فرد)، `occurrences` و `last_seen_at` |
| `api.py` / `api_urls.py` | `POST /api/events/` (Engine) و `GET /api/events/summary/` (شمارنده‌های زنده‌ی صفحه) |
| `summary.py` | محاسبه‌ی شمارنده‌ها: رویدادهای باز، رویدادهای امروز، دوربین‌های در حال هشدار، آخرین رویدادها |
| `filters.py` | فرم فیلتر کانال مدیریتی (تاریخ، ماژول، نوع، دوربین، وضعیت، شناسه‌ی فرد) |
| `export.py` | خروجی CSV (با فارسی درست در Excel) |
| `views.py` / `urls.py` | صفحه‌ی لیست، جزئیات، تأیید (Acknowledge)، **انتساب «این شخص کیست؟» توسط اپراتور** (با سابقه‌ی تغییرات)، نمایش تصویر فقط برای کاربر واردشده، گزارش چاپی |
| `maintenance.py` | پاک‌سازی رویدادهای قدیمی و پشتیبان‌گیری از دیتابیس |
| `signals.py` | پاک کردن فایل‌های تصویر/کلیپ وقتی رویداد حذف می‌شود |
| `management/commands/run_maintenance.py` | **کار روزانه**: پاک‌سازی بیشتر از `retention_days` + پشتیبان |
| `tests.py` | تست API، فیلترها، تأیید، خروجی، پاک‌سازی، پشتیبان |

## پوشه‌ی `engine/` (موتور GPU)

موتور تمام پردازش ویدیو را انجام می‌دهد و هرگز به پایگاه داده دست نمی‌زند. هر پوشه README خودش را دارد.

| پوشه | کار |
|------|-----|
| `core/` | `main.py` (دستورهای run / offline / replay)، تنظیمات، pipeline، منبع‌ها، بررسی وجود مدل‌ها |
| `perception/` | تشخیص‌دهنده‌ها (Ultralytics و ONNX)، ردیاب، ReID |
| `modules/` | ماژول‌ها؛ فعلاً `ppe/` (کلاه، جلیقه، کفش ایمنی) |
| `events/` | ماشین حالت رویداد و عکس‌برداری |
| `identity/` | گالری ظاهر برای ادغام تخلف‌های تکراری (نه شناسایی هویت) |
| `render/` | کشیدن روی تصویر، پخش زنده‌ی MJPEG، نوشتن ویدیو |
| `web_client/` | ارسال رویداد و ضربان قلب به وب، صف ارسال مجدد |
| `config/` | `engine.example.yaml` |
| `tools/` | بنچمارک و بررسی ONNX |
| `tests/` | تست‌ها (بدون GPU، با تشخیص‌دهنده‌ی ساختگی) |

## پوشه‌ی `desktop/` (برنامه‌ی دسکتاپ ویندوز)

`launcher/` (اجرای وب و موتور، سینی سیستم، پنجره)، `build/` (اسکریپت‌های ساخت)، `installer/` (Inno Setup)، `config/` (تنظیم موتور نصب‌شده)، `tests/`.

## دستورهای مهم (از داخل پوشه‌ی `web`)

| دستور | کاربرد |
|---|---|
| `python manage.py migrate` | بعد از هر تغییر در `models.py` |
| `python manage.py run_maintenance` | پاک‌سازی قدیمی‌ها + پشتیبان (روزانه اجرا شود) |
| `python manage.py test` | اجرای همه‌ی تست‌ها |

## کارهای رایج

- **افزودن دوربین و انتخاب ماژول‌های آن:** Settings ← Cameras ← Manage (فقط مدیر).
- **رفتن به PostgreSQL:** `docker compose -f deploy/docker-compose.yml up -d`، با `POSTGRES_PASSWORD` که خودتان تعیین می‌کنید؛ بعد در `.env` بنویسید `DATABASE_URL=postgres://app:<رمز>@127.0.0.1:5432/app` و `migrate` بزنید.
- **اجرای خودکار روزانه‌ی نگهداری در ویندوز:** در Task Scheduler یک Task روزانه بسازید که این را اجرا کند:
  `<مسیر python>\python.exe <مسیر پروژه>\web\manage.py run_maintenance`
  (در نسخه‌ی نصب‌شده launcher خودش این کار را روزانه انجام می‌دهد)
- **نوع رویداد جدید:** در `registry.py` به `event_types` همان ماژول اضافه کنید و جدول `docs/engine_api.md` را به‌روز کنید.
- **مشتری جدید:** پوشه‌ی `profiles/default` را کپی کنید، `profile.yaml` و لوگو را عوض کنید، و در `.env` مقدار `SITE_PROFILE` را به اسم پوشه‌ی جدید تغییر دهید.
- **ماژول جدید:** یک مورد در `registry.py` اضافه کنید، کلیدش را در `enabled_modules` پروفایل بنویسید، و ترجمه‌ی اسمش را به `django.po` اضافه کنید.
- **متن جدید در صفحه:** آن را داخل `{% translate "..." %}` بنویسید، ترجمه را به `django.po` اضافه کنید، و `python scripts/compile_translations.py` را اجرا کنید.
- **صفحه‌ی فقط-ادمین:** روی view از `@admin_required` استفاده کنید.
